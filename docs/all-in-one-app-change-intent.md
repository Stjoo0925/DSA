# 올인원 앱 전환 의도

## 배경

기존 구조는 다음 전제를 두고 있었다.

- 실행 파일은 배치 프로그램 역할만 수행한다.
- 설정값은 환경변수로 주입한다.
- 스케줄 작업은 운영자가 별도로 등록한다.

이 방식은 개발자 입장에서는 단순하지만, 실제 운영에서는 아래 불편이 있다.

- 환경변수를 직접 등록해야 한다.
- `keepalive`와 `daily-report`를 별도 스케줄러에서 각각 설정해야 한다.
- 설치 후 바로 사용할 수 있는 형태가 아니다.
- 운영자가 실행 파일만 보고도 무엇을 해야 하는지 파악하기 어렵다.

## 바꾸려는 방향

이 프로젝트는 단순 배치가 아니라, 실행 파일 하나만 배포해도 운영 가능한 형태로 가는 것이 더 적합하다.

목표는 아래와 같다.

- 단일 실행 파일(`dsa.exe`) 중심 배포
- 실행 파일 옆 설정 파일(`dsa.config.json`) 사용
- 환경변수 없이도 기본 운영 가능
- 앱이 직접 작업 스케줄러 등록 가능
- 설치형 패키지(`setup.exe`)로 묶기 쉬운 구조

## 핵심 변경 의도

### 1. 환경변수 의존도 축소

기존에는 `DATABASE_URL`, `KAKAOWORK_WEBHOOK_URL` 등 핵심 설정을 환경변수에 넣어야만 동작했다.

이제는 실행 파일과 같은 위치의 `dsa.config.json`을 기본 설정 저장소로 사용하도록 바꾸려 한다.

이렇게 하면 운영자는 아래처럼 이해하면 된다.

- 프로그램 설치
- 설정 파일 수정
- 실행 또는 스케줄 등록

즉, 서버 환경변수 조작 없이도 운영 가능하게 만드는 것이 목적이다.

### 2. 스케줄 등록도 앱 안으로 포함

기존에는 `.bat` 파일이나 작업 스케줄러 수동 등록이 필요했다.

하지만 올인원 앱 구조에서는 아래처럼 가는 편이 맞다.

- 앱이 `register-tasks` 명령으로 스케줄러를 직접 등록
- 앱이 `unregister-tasks` 명령으로 스케줄러를 직접 삭제

이렇게 하면 설치 후 운영자가 따로 명령어를 조합할 필요가 줄어든다.

### 3. 설치형 패키지 대응

Inno Setup으로 설치 파일을 만들 때도, 환경변수 기반 구조보다 설정 파일 기반 구조가 훨씬 다루기 쉽다.

이유는 아래와 같다.

- 설치 후 설정 파일 위치가 명확하다
- 사용자마다 다른 값을 파일로 관리할 수 있다
- 추후 설정 UI를 붙이기 쉽다
- 제거/재설치 시에도 구조가 단순하다

## 이번 변경 범위

이번 변경은 아래 범위를 목표로 한다.

- `dsa.config.json` 기반 설정 로딩 지원
- 환경변수는 보조 수단으로 유지
- `init-config` 명령 추가
- `register-tasks` 명령 추가
- `unregister-tasks` 명령 추가
- README를 실행 파일 중심 사용법으로 수정
- 설치 파일 생성 스크립트 유지

## 아직 남아 있는 과제

현재 구조만으로도 올인원에 가까워지지만, 완전한 의미의 앱으로 보려면 아래가 후속 과제다.

- 설정 파일을 수정할 수 있는 간단한 UI
- 카카오워크 연결 테스트 버튼
- DB 연결 테스트 버튼
- 작업 스케줄러 상태 조회 기능
- 로그 보기 화면

즉, 현재 단계는 "배치 프로그램"에서 "설치 가능한 운영 앱"으로 넘어가기 위한 1차 구조 개편이다.

## 결론

이번 방향 전환의 핵심은 다음 한 줄로 정리할 수 있다.

`개발자용 실행 도구`에서 `운영자가 바로 설치하고 설정해서 쓸 수 있는 실행 파일`로 바꾸는 것.

따라서 앞으로의 설계 판단 기준도 아래처럼 잡는다.

- 환경변수보다 설정 파일 우선
- 수동 스케줄 등록보다 앱 내부 등록 우선
- 소스 실행보다 단일 실행 파일 배포 우선
- 추후 UI 확장이 쉬운 구조 우선
